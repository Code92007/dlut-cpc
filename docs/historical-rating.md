# 校史 Rating v2 与赛场表现

`/elo` 从本站实时、已确认的正式参赛结果重放个人积分曲线；`/performance` 展示赛时 AC 对应的题目难度与升级目标。两种 Rating 独立，早年没有题目 Rating 仍可计算个人积分。未导入 CF 或外部 XCPC 个人分数。

## 每场有涨有跌

实现 `historical_rating.py`，版本 `dlut-award-performance-v2`。初始 1500，按实际日期计算，每位成员：

`R_new = R_old + α × (P − R_old)`

前三场 α=0.5，此后 α=0.3。P 高于个人赛前分就涨，低于就跌；相同队伍结果对赛前分不同的成员可以产生相反方向的变化。参赛不自动加分，长期重复同水平表现会收敛到该水平。队伍结果是三人的共同观测，不用于猜测个人解题贡献。

P 首先由**实际奖项**选档：

| 实际奖项 | 普通区域赛表现分范围 | 名次参考区间 |
| --- | --- | --- |
| 金牌 | 2600–3200 | 0–10% |
| 银牌 | 1900–2400 | 10–30% |
| 铜牌 | 1300–1800 | 30–60% |
| 铁牌 | 800–1200 | 60–100% |

q=(r−0.5)/N，r 为正式名次，N 为正式队数。在本档参考区间内，将 q 线性映射为表现分从上限到下限，超出区间截到本档边界。参考区间**不决定实际奖项**；历史特殊奖牌比例、正式有效队分母等差异不会把银牌映射到金牌档。首尾修正避免出现极端名次不连续。

EC Final（东亚/中国区决赛）、CCPC Final 的参赛资格与阵容更强：所有奖项的 P 在普通区域赛基准上 **+300**，再计算个人涨跌。例：决赛金牌 P=2900–3500，决赛银牌 P=2200–2700。该数值是公开、可替换的初始场强先验，并非用全国完整阵容拟合的参数；不声称各类决赛强度完全相同。普通区域站之间和年代之间暂不额外调整。该调整不按决赛次数累计，也不只奖励金牌。

例如成熟选手赛前 2400，普通区域赛银牌 P=2200，本场 Δ=−60。持续五场普通区域赛金牌的成熟峰值高于六场普通区域赛银牌；但这不是按生涯金牌数量排序，后续发挥变差仍会掉分。v1 仅按分位、用队伍平均分计算预期，会低估实际金牌和决赛、并使不同个人履历共享同一预期；v2 全历史重算，不能直接比较两个版本的分数。

## 资格、身份与峰值

- 仅 ICPC/CCPC 正式区域赛及国内区决赛/总决赛。排除打星、正式资格未明、邀请赛、女生专场、网络赛、预选、省赛和世界总决赛。
- 必须有完整有效日期、实际奖项、正式名次/正式队数、已确认三位不同的稳定成员 ID。不用奖牌猜名次，不用总榜替代正式榜；缺失结果不作为失利。
- 同场同名单去重；同日同一成员出现在多队则暂停这些冲突记录并列出原因。输入顺序不影响结果，没有用未来比赛信息计算过去积分。
- 三场后进入正式榜；历史峰值仅取第三场及之后的最高赛后分。一至两场单列暂定，零场不赋分。退役不扣分，最后参赛分保留。
- B=max(150,400/sqrt(1+n/3)) 是样本量参考带，保守分=最后参赛分−B，不是置信区间。主表显示计分战绩、最后一场涨跌；点击姓名查看每场奖项、名次、表现分、决赛调整与曲线。

`/api/analytics` 只读，与 `/api/site` 读取同一份实时 SQLite 数据。每日同步或管理员审核、补录、纠错后，下次打开页面重新计算。输入指纹包含奖项、日期、比赛、正式名次、资格和名单；完整轨迹可下载 JSON 复核。归档及个人积分均不修改原成绩库。

局限：早年部分档案只收录获牌队，部分只有名次没有正式队总数；这类记录仍不计分。固定队友个人贡献不可分离。不同年代的绝对实力和各站场强尚未校准。应继续补全完整全国榜及身份关联，用按时间留出的后续比赛检验预测，再发布新版本。分数采用本站独立标尺，公式并非 CF 或经典零和 Elo。

## 完整工作簿与 2026 六站

`data/team_performances.json` 保留用户原工作簿《DLUT主校区区域赛_阶段速览_2020-2026.xlsx》“阶段速览”第2–161行，**160条全部收录**。原始单元格数值及数字格式共同决定展示文字（如 `"稳金 "0`），保留空白、星号和“仅罚时”。原始文件在 `/assets/team-performance-2020-2026.xlsx`。

匹配其同批《统计数据.json》证据及实时成绩库的唯一学校/队名/实际日期，保留稳定 honorId、来源行号、实际比赛年、赛季、原榜队伍 ID、AC、原榜链接与完整升级计划。原截图误记的“2020 ICPC 上海 / 梦觉流莺时一声”，已按完整工作簿与实际日期补正为2021年。

另新增2026西安、长春、成都、武汉、乐山、南京六个已完赛区域站 **23条**（主校区16、盘锦7），共183条。题目 R 来自2026-11-14在线 CF-Bot `/api/regional-catalog`；历史160条保留原表快照 R，不在后台悄悄换数。原表5条暂无评级、2条0AC，最高R均为空，不记为0分。所有183条均关联当前成绩。

新增数据由原榜完整赛时提交恢复 AC，重复提交 ID 取最终判定，排除赛后提交和 ignore；XCPCIO 处理毫秒，ICCPC 仅4为AC，tkind0/1正式、2打星。以学校和队名唯一关联，核验正式资格。全场 `(正式资格, AC集合)` 多重集与 CF-Bot 固定匿名快照完全一致；原榜身份来自原始 team/organizations，不从匿名行猜队名。归档保留实际下载 SHA256、CF-Bot 快照 SHA256、题目 R 和全场门槛，可追溯来源。部分源站重新序列化了旧JSON，下载哈希与评级时的原始文件不同，故核对内容而不冒用旧文件哈希。

阶段顺序：铁牌→速铜→稳铜→速银→稳银→速金→稳金。速=该奖项末队题数，仍须比较罚时；稳=未获得该奖项（含以上）队伍的最高题数+1。实际奖项和题数共同确定当前速/稳档。保留原有AC，再选择最低R未解题使新增最高难度最小。若低奖项稳档与高奖项稳档重合，该低档留空；下一/下两阶段按固定顺序，不能跳过空档。目标R只取新增集合，可能低于已解最高R。打星不推实际获奖；原表 Attention 的训练参考明确带星。乐山升级门槛使用原榜300支正式队，本站成绩库使用CPC Finder299支口径，页面说明差异，不修改成绩库。

## 可重复构建与发布

`tools/build_team_performances.py` 离线构建，不联网、不写原表或数据库。构建时需要 openpyxl；运行服务不需要该依赖。参数：

- `--workbook` 原xlsx；`--report` 同批统计数据.json；`--live` 当前/api/site快照；`--catalog` 当前CF-Bot/api/regional-catalog快照。
- `--evidence` 文件夹：xian/chengdu/wuhan/nanjing的`{site}-config/team/run/organizations.json`，changchun/leshan的`{site}-rank.json`。来源在每场`statistics.source_url`及CF-Bot目录`regional_2026_sources.json`。
- `--anonymous` CF-Bot目录，内含`historical_standings/*.json`；`--output data/team_performances.json`。

`python3 -m unittest discover -s tests` 和 `node --test tests/*.mjs` 验证公式、正负变化、决赛强度、无未来泄漏、身份门槛、空档和补题，以及前端筛选/渲染。发布前备份生产数据库，更新代码及归档并重建容器；不能用本地SQLite覆盖生产。发布后核对在线重放结果与本地一致，并确认成绩和成员身份未改变。
