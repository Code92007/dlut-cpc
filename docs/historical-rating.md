# 校史积分与赛场表现 v1

## 目标与取舍

`/performance` 展示队内整理的解题难度与阶段；`/elo` 独立从本站确认的正式参赛结果生成个人 Elo 尺度积分。不依赖 2020 年以后才有的题目 Rating，不把 CF 或外部 XCPC 分数拼接进校史排名。

外部参考：[XCPC Elo](https://github.com/Zzzzzzyt/xcpc-elo) 可从 SRK 构建个人积分；[XCPC Sight](https://github.com/JunjieCharles/xcpc-sight) 按赛季独立从 1400 起算，说明只在同系列中比较。直接复用现成分数不能覆盖本站早年身份补录，也不能解决各系列独立初始化的问题。本站采用可版本化、可重算的独立模型，并保留两者的参考入口。

当前正式成绩库并非完整全国榜，早年有只收录获牌队的选择偏差。因此 v1 是**以名次分位为锚点的 Elo 试行模型**，不能称为已校准的绝对个人实力榜。排名比较的前提及局限同时出现在产品页面。

## 计算规则

实现：`historical_rating.py`；版本：`dlut-percentile-elo-v1`。

- 全年代统一初始 1500，按实际比赛日期、规范比赛标题和稳定成绩 ID 排序。名单使用成员 ID，支持数据库已经确认的重名区分、身份合并与补录。
- 正式名次 r / 正式队数 N；要求 N >= 2 且 1 <= r <= N。S = (N - r + 0.5) / N。半名次修正使首尾有限，同名次同分位。
- 三名成员赛前积分算术平均为 T；E = 1 / (1 + 10^((1500 - T) / 400))。
- 每名成员 R' = R + K(S - E)，K = 400 / sqrt(1 + n/5)，n 为该成员之前有效场次。所有计算保留浮点精度，前端显示整数，逐场变化保留小数。
- 展示的分位表现分 P = 1500 + 400 log10(S/(1-S))。这不是题目难度分，也不与 CF 或外部 XCPC Rating 对标。
- 第三场后进入正式榜；峰值只取第三场及之后的赛后积分。1–2 场为暂定，0 场不赋初始分，显示无数据。最后参赛积分没有时间衰减，避免退役天然扣分。
- B = max(150, 400/sqrt(1+n/3)) 为样本量参考带，保守分 = 最后参赛积分 - B；B **不是统计置信区间**。固定队友的贡献不可辨识，页面显示阵容数量，只有一套阵容时单独提示。
- 同日同一成员出现在两套队伍里时，两条记录均暂不计分并列出冲突；同日互不重叠的队伍没有状态依赖。同场同名单的重复记录只计一次。

每场参赛群体的中位水平都被统一视作 1500。这是明确的先验假设，不能校准决赛与区域赛、不同年份及赛站的参赛群体差异；同场相对成绩可比，跨年代绝对实力尚不可识别。参赛次数影响收敛和峰值机会，正式榜门槛只能减少单次偶然性，不能消除这些差异。

## 计分数据门槛

仅 ICPC / CCPC 正式区域赛、总决赛、东亚 / 中国区决赛；排除打星、资格未明、网络赛、预选、省赛、邀请赛、女生专场、世界总决赛。必须有合法完整日期、完整已确认三人名单、稳定成员 ID、正式名次与正式队数。奖项未知不影响有效排名计分，不能用奖牌猜名次；总榜不能替代正式榜。缺少记录不视为未参赛或失利。

`/api/analytics` 返回有效人数、场次、逐人完整历史和未计分记录及原因。所有本站成员均可在“全部成员”中找到，不能计分者保留空值，不自动拼接同名。输入指纹覆盖参与计算的名次、日期和名单，规则另有版本号；补录旧比赛或纠错后，从头重算后续轨迹。

接口只读、不写积分数据库。它读取与 `/api/site` 相同的实时 SQLite 结果，已有每日同步、管理员审核或补录完成后下次打开页面即生效，无需复制数据库或维护第二份积分。前端整页会话保留同一次分析结果，重新载入页面获取最新结果。完整 JSON 可下载以复核或离线比较。

## 赛场表现归档

`data/team_performances.json` 完整保留用户所给截图第 2–48 行的 47 条记录。每条有稳定条目 ID、原表行号、原表年份、赛事、赛站、队名、已解最高 R、阶段和后续目标。原始截图公开于 `/assets/team-performance-20261114.png`。

与成绩库能唯一核对的记录通过 `honorId` 关联，展示独立的实际日期、名单、正式资格、名次和来源；年份按原表保留，延期赛事可能跨年。原表“2020 ICPC 上海 / 梦觉流莺时一声”与现档案赛季不一致，暂不关联，不把相似队名当作证据。星号及空白阶段保留；空白不猜值。原图没有题号、Rating 来源和“速/稳”完整判定细则，产品明确显示待补，不伪造题目级 AC 证据，也不据最高 R 推断所有较低难度题均已通过。

后续维护此 JSON 可增加经核验的条目、修正对应行、补题号及难度来源；该表不改变成绩、名单或积分。浏览器支持筛选后导出 UTF-8 BOM CSV，并防止公式注入。

## 完整公平体系的后续门槛

1. 补齐早年的未获牌成绩和完整榜单，逐场确认正式队口径及具体三人身份，记录档案覆盖范围，减少选择偏差。
2. 使用全国全场队伍和跨年跨队成员的稳定身份图，建立带不确定性的团队对局模型；对无法连通的年代单独标注，不能凭公式得到不存在的跨年代证据。
3. 用完整队伍结果估计赛站强度与年代漂移；更换队友的数据才能逐步识别个人贡献。题目难度作为额外证据，不能作为全年代都有的必要条件。
4. 按时间留出后续比赛，评价预测排名的相关性、两两胜率及区间覆盖率；避免使用赛后信息预测同场，再依据公开诊断决定新版本。
5. 每次改变模型或参数提升版本，保存输入快照与可复算报告，解释排名变化。当前参数是透明的初始规则，未宣称通过全国预测验证。

## 验证与发布

`python3 -m unittest discover -s tests` 验证历史无 Rating 时计分、正式 CCPC 赛站识别、身份与名次门槛、重复与冲突、输入顺序无关、历史无未来泄漏、暂定及峰值规则。`node --test tests/*.mjs` 验证前端排序、筛选与原站回归。发布仅更新代码和归档，先备份生产数据库，不能用本地 SQLite 覆盖生产。
